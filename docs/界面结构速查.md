# 金蝶云星空 8.2 界面结构速查

> 站点：`https://tlym.ik3cloud.com/k3cloud`
> 采集日期：2026-09-18，主 quasar 版本 8.2.0，网页端（Kendo UI + 自绘 kd-* 控件）
> **所有结论均为实测**，不是文档推测。

---

## 全局规律

### 1. 单文档，没有 iframe
整个 k3cloud 是一个 SPA（`/k3cloud/html5/dform.aspx?formId=BOS_HtmlConsole`），列表、单据都在同一 document 里切换。
**但**：eval_all_frames 仍保留，防止个别界面回归 iframe。

### 2. 控件 id 的构成
```
{pageId/GUID片段}-{字段名}-{控件后缀}
```
同一页面可能有**多份** DOM（多标签页，切走后 DOM 仍留在 document 里），
**因此任何定位都必须叠加可见性过滤**：

```js
const vis = e => { const r = e.getBoundingClientRect(); const s = getComputedStyle(e);
  return r.width>0 && r.height>0 && s.display!=='none' && s.visibility!=='hidden'; };
```
不过滤会从"销售出库单列表"里取到元素，导致操作打错帧。

### 3. 大小写混用（踩过的坑）
| 位置 | 后缀 | 大小写 |
|---|---|---|
| 表单字段 | `-FXXX-EDITOR_c` | **大写** `_c` |
| 过滤对话框 字段/比较符 | `_row_Add_PART_Fileds` / `_row_Add_PPART_CompareType` | 小写 `row_Add` |
| 过滤对话框 值输入框 | `_ROW_ADD_PPART_VALUE_c` | **全大写** `ROW_ADD` |

CSS 属性选择器大小写敏感 → **禁止按 id 后缀定位过滤对话框的值输入框**，改成按 `<tr>` 行容器 + `data-role` 找。

### 4. 事件是委托绑定的：`el.click()` 经常无效
必须用**完整鼠标事件序列**：
```js
['mousedown','mouseup','click'].forEach(t =>
  label.dispatchEvent(new MouseEvent(t, {bubbles:true, cancelable:true, view:window})));
```
复选框（`input[data-field="SELECTED"]`）自带 `onclick="return false"`，点它没用，要**点同级的 `.k-checkbox-label`**。

### 5. Kendo DatePicker 必须走 API
直接改 `input.value` 不会同步到 model：
```js
$(el).data('kendoDatePicker').value(new Date('2026/09/25'));
$(el).data('kendoDatePicker').trigger('change');
```

### 6. ★标签页管理：清场口径 + 真标签的选择器（2026-09-21）

**清场口径（用户确认）**：**生成凭证之后**（下推链最后一步）关掉所有标签页，
**只保留「销售出库单列表」**。为什么要清：SPA 把每个开过的页面 DOM 都留在 document 里，
标签越堆越多，命中「隐藏页面」元素的概率越高。

**★★ 定位坑：`.k-item` 不只匹配标签页！**
工具栏的每个菜单项（新增/保存/提交…）也是 `li.k-item.kdmenuitem`，
直接 `querySelectorAll('.k-item')` 会捞出 20+ 个假标签。

| 对象 | 选择器 |
|---|---|
| 标签条容器 | `ul.k-tabstrip-items`（可见的那个） |
| **真标签页** | `ul.k-tabstrip-items > li.k-item.contentHeadEL` |
| 关闭按钮 | 标签内 `span.k-i-close.mainTabCloseButton` |

- 关标签用**真实鼠标**点关闭按钮坐标（合成 click 对 Kendo 不灵）。
- **★★★ 必须先激活该标签、再点它的 ✕（2026-09-21 踩坑）**：点**非激活**标签的 ✕
  **只切换到它、不关闭**（看起来「点了没反应」）。正确顺序：
  `点标签本体(tx,ty) → 等 1.5s → 重新取标签列表(坐标会变) → 点该标签的✕`。
  直接连点 ✕ 会一直原地打转。
- **★ 关闭确认不是 `.k-window`，是内嵌警告条**：点 ✕（或工具栏「退出」）后弹出
  `.kd-el-popmessage.kd-message-question`（id 尾 `-POPFLOATEMESSAGE`），
  文案两种：`内容已经修改，是否保存？` / `关闭页签会丢失尚未保存的下推生成数据。想要保存单据吗？`，
  按钮是 `<button class="k-button">` 三个：**是 / 否 / 取消**。
  **丢弃就点「否」**（`否` 按钮中心 ≈ (134,164)，随窗口宽度变化，务必实时取 rect）。
  这套弹出**不是** `.k-window`，用 `.k-window` 去找会一无所获。
- 关一个位置就变，所以**每轮重新取标签列表**；先关非激活的（从右往左），
  非保留的激活标签最后关，关完再把保留的标签**切回前台**。
- 有些功能页**一打开就弹一个 `.k-window`「过滤」对话框**（实测：凭证查询），
  它会浮在上面把后续所有真实鼠标点击拦掉，报错形如
  `<a aria-label="Close"> … intercepts pointer events` → 清场时要顺带关掉
  （点 `[aria-label="Close"]`，且只在文案命中「关闭/放弃/未保存」时才点「确定」）。

> 同名标签（如两张都叫「应收单 - 新增」）时 `activate_tab(名字)` **只会命中第一个**，
> 要按**序号**操作：`tabs()[i]` 然后用 `tx/ty` 点击。

**★ 从顶部搜索打开功能是「替换当前标签」，不是新增**（实测连续打开 3 个功能后仍只有 1 个标签）。
所以「保留销售出库单列表」在实现上是：关掉其它标签 → 若出库单列表已不在 → **重新打开一个**。
```bash
python src/clean_tabs.py --go --keep-name 销售出库单列表
```

#### ⚠️⚠️ 表头复选框是**三态**语义（2026-09-21 定位到根因）

| 当前状态 | 点表头的效果 |
|---|---|
| 一行没选 | **全选**（不是「取消」！） |
| 部分选中（例如只勾了 1 行） | **全选** |
| 全部选中 | 全清 |

实测证据（跑 `src/probe_filter_select.py` 第 5 步复现）：
```
只勾第 1 行      → selected_count = 1
点表头第 1 次    → selected_count = 565   ← 老实现到此结束，留下 565 行全选！
点表头第 2 次    → selected_count = 0
```
⇒ 「首屏残留 555 行选中」就是这个根因：**部分选中时点一次 = 全选**，
  接着再 `select_rows()` 勾选 → 选中状态整个乱掉，可能推错单据。
⇒ 正确实现：**循环点表头并读 `selected_count()` 直到归零**（0 行时千万别点，点了反而全选）。
  `steps.py::clear_selection()` 已是循环版（最多 4 次，每轮打日志）。

#### ⚠️ 行级复选框必须用**真实鼠标**点（2026-09-21）

行的复选框 HTML：
```html
<div data-role="checkbox" class="kd-grid-celldiv kd-grid-selector" data-field="SELECTED" data-rowid="1">
  <input type="checkbox" onclick="return false;" class="k-checkbox gridCheck gridCheckCell" ...>
```
`onclick="return false;"` 挡掉默认切换，金蝶在**祖先容器**上做事件委托 →
派发合成 `MouseEvent` **勾不上、还不报错**（静默失败）。
必须 `page.mouse.click(x, y)`，且点击前先 `scrollIntoView` 并校验未被遮挡。

**另一个同类坑**：老实现扫 `document.querySelectorAll('tbody tr')` 会命中
**隐藏页面**的列表（SPA 里开过的页面 DOM 全留着），于是"点了 46 个复选框"全在隐藏表格里，
页面上 `selected_count()` 仍是 0。凡扫 DOM 必先过可见性 + 限定当前可见 grid。

#### ⚠️ 过滤条件末行会被静默丢掉（2026-09-21）

金蝶是在 input 事件之后**异步**把条件 commit 进内部模型的。
**最后一行条件写完值立刻点确定** → 那一行条件丢失 → 现象是「4 张单只筛出 3 张」，
而日志里每行都显示"设置成功"，完全看不出问题（最难查的那种）。
前面的行之所以没事，只因后面还有"设逻辑 / 加下一行"的操作，顺带等到了 commit 时间。

⇒ 修法：`kdFilterAdd` 后等 450ms 再写值；点确定前再等 1200ms；
  并用 `_read_condition_rows()` **回读自检**（条件行数 + 值都要对得上）。
⇒ 回读时注意：值输入框 id 是**全大写** `_ROW_ADD_PPART_VALUE_c`，
  `[id$="_row_Add_PPART_VALUE_c"]`（CSS 属性选择器大小写敏感）**命中不到**，
  会误判成"值没写进去"；要按 `ppart_value` 转小写查找。


### 7. ★顶部全功能搜索：在输入框里打字根本不触发搜索（2026-09-21）

实测：`type()` 期间 **0 个网络请求**，面板一直显示「最近搜索历史」；
按 Enter 只是关掉面板（会发 5~7 个 kdsvc 请求，但不打开任何功能）。

**搜索只在「面板被打开的那一瞬间」发起**，用的是输入框里已有的值。所以流程必须是：

```
Esc 关掉面板 → 点图标开面板 → 清空 + 输入关键字 → ★Esc 关掉 → 再点图标重开
                                                        ↑ 这一步才真正去搜
→ 结果出现在 .kd-fullsearch-item-container → 点中目标条目
```

| 元素 | 选择器 |
|---|---|
| 搜索图标 | `.kd-fullsearch-searchicon`（面板打开时它被隐藏，所以要先 Esc） |
| 输入框 | `input.kd-appplat-searchinput`（placeholder「请输入内容进行搜索」） |
| 结果面板 | `.kdfullsearchpopextend`（标题形如 `搜索"XXX" 共N项`） |
| 结果条目 | `.kd-fullsearch-item-container`（文本 = 编码+名称 \n 菜单路径） |

**★ 重名要用「菜单路径」消歧**：同名功能常有 2~3 条。实测：
`销售出库单列表` 有 3 条（供应链>销售管理>出货处理 / 供应链>库存管理>销售出入库 /
电商与分销>电商集成>电商销售单据对接），**正确的那条是「供应链>销售管理>出货处理」**。
代码里固化成 `KingdeeUI.MENU_PATH_HINT`，不给提示且有多条同名结果时**直接报错**，不猜。

**★★ 2026-09-22 补：结果条目必须真实鼠标点，且「已开着就别再搜」**

1. `结果条目.click()` / `get_by_text(...).click()` 会**超时**，报
   `<div class="kd-form-collapse-container"> … intercepts pointer events`
   —— 条目 DOM 可见，但指针事件被功能页外壳的**折叠容器**接走。
   ⇒ 必须 `js_pos` 取条目中心坐标 → `document.elementFromPoint(cx,cy)` **命中检测** →
   `page.mouse.click(cx, cy)`。
   ⇒ 坐标可能在视口外（实测 `y=-32`），先 `el.scrollIntoView({block:'start'})` 再取。
   ⇒ 兜底 `locator.click()` 只在真实鼠标失败后试，且必须捕获异常。
2. **目标列表已经开着就直接 `activate_tab`，不要重复搜** —— 会新开第二个同名标签，
   之后 `activate_tab(名字)` 只命中第一个 → 操作落到错的那个（SF-29）。
   入口函数 `steps.open_menu_by_search()` 已加此分支。
3. 搜之前先关掉占用焦点的同名标签（`src/gy_closetab.py <关键字>`），否则面板点不开。

**★★ 2026-09-22 补：挡路的 `.k-window`（含别人残留的）**

- 有些功能页一打开就弹「过滤」对话框，浮在最上层拦掉所有真实鼠标点击
  （`src/clean_tabs.py` 的 `close_stray_windows()` 会顺手关掉）。
- **更麻烦的是别人残留的「处理结果」批处理失败窗** —— 内容是**别人的单**
  （实测 `183306=XSCKD-101-202512-S0283`，2025-12、组织 101），但同样浮在最上层。
  ⇒ 先 `src/close_result_dlg.py`（或技能侧 `kd_stray.py --dump`）**dump 内容确认不是自己的单**，
  再**真实鼠标点 ✕ / 「退出」**关掉。合成 click 对 `.k-window` 无效。
  ⇒ ⚠️ 关闭时**点「退出/取消/关闭」，不要点「确定」** —— 误点会真提交/真保存。
- 由此推论：**账套里有别的用户/组织在并发跑单**，浏览器会话是**共享**的
  （2026-09-22 清场后仅剩 1 个标签，稍后再看已冒出别人新开的 4 个）。
  **不属于自己的标签不要动**；单据号会**跳号**（`-0001` → `-0003`），**跳号 ≠ 丢单**。

**★★ 2026-09-22 补：凭证不能用 `FBillNo` 找**

`ExecuteBillQuery` 查 `GL_VOUCHER` 回来的 **`FBillNo` 是内部 FID**（纯数字，如 `205495`），
**不是界面上的凭证字号「转 66」**。定位凭证要**按摘要原文 + 日期**筛：
```python
kq.rows("GL_VOUCHER", "FBillNo,FDate,FDocumentStatus,FEXPLANATION,FACCOUNTID.FName,FDEBIT,FCREDIT",
        f"FEXPLANATION = '{摘要原文}' and FDATE >= '2026-09-29 00:00:00'")
```
另：**专票明细税额用行级 `FDETAILTAXAMOUNT`**；误用单头 `FTaxAmount` 会**按行重复**
（5 行合计变成 `2358.41 × 5`）。

## 界面一：销售出库单列表

### 工具栏菜单（`.kdmenuitem-content`）
| 文字 | id 后缀 |
|---|---|
| 过滤 | `-tbReadFilter` / `-tbFilter` |
| **下推** | `-tbBusinessPush` |
| 凭证 | `-tbVoucher` |
| 审核 / 反审核 | `-tbApprove` / `-tbUnApprove` |
| 新增 / 删除 / 刷新 | `-tbNew` / `-tbDelete` / `-tbRefresh` |

> id 里的 `-__definesub__` 需 replace 成 `-`，替换后 = 可见版 id。（用户旧脚本逻辑，已实测确认正确）

### 列表结构：**列头和数据是两个 table**
- `table` 里表头那个有 20 个 `th`（含 `data-title`）
- `table.k-selectable` 是数据体
- 关键列索引：日期=3、**单据编号=4**、**账务日期=5**、客户=7

### 搜索框（两个，placeholder 不同）
| placeholder | 含义 |
|---|---|
| `请输入关键字` | 单据编号 |
| `请选择内容` | 客户 |

输入后必须派发 input/change + Enter 事件序列。

### 行勾选
- 表头全选：`input.gridCheckHeader`（`data-rowid="-99"`，**没有** `data-field`）
- 数据行：`input.gridCheck.gridCheckCell`（**有** `data-field="SELECTED"` + `data-rowid="1..N"`）
- ⚠️ **行级勾选必须真实鼠标 `page.mouse.click(x, y)`**：行复选框带
  `onclick="return false;"`，金蝶在**祖先容器**上做事件委托 → 派发合成 MouseEvent
  **勾不上且不报错**。（表头那个仍可用「label 完整鼠标序列」派发，`clear_selection()` 就这么做。）
- ⚠️ 扫行时**不能**直接 `document.querySelectorAll('tbody tr')`（会命中隐藏页面的列表），
  必须 `Array.from(document.querySelectorAll('table.k-selectable')).filter(vis)[0]`。
- ⚠️ 点表头是**三态**语义（未选/部分选中 → 全选；全选 → 全清）：
  要清空必须**循环点到 `selected_count()` 归零**。详见上面「全局规律 6」。

### 分页与真实选中数
- 列表每页加载 **200 行**，滚动容器 `.k-grid-content.k-auto-scrollable`
- DOM 里 `:checked` 最多数到 201 → **不能用来判断选中数**
- 真实选中数在分页栏 `.kd-grid-pager-col`：`已选 N 行`
- **全选覆盖全部结果（实测 599 行），不是当页 200 行**

### ★ 列表是虚拟滚动：DOM 只有 ~200 行，读全量必须走数据源（2026-09-21）
`tbody tr` 永远只渲染约 200 行（1067 行的出库单列表只看得到前 200）→ **别从 DOM 读全量**。
```js
const g = jQuery(el).data('kendoKDGrid') || jQuery(el).data('kendoGrid');  // 注意是 kendoKDGrid
const rows = g.dataSource.data().map(d => d.toJSON ? d.toJSON() : d);      // 全量行
```
数据源字段名 ≠ 表头文案。实测出库单列表字段：
`FBILLNO`(单据编号) / `FCUSTOMERID_FNAME`(客户) / `FDATE1`(账务日期) / `FREALQTY`(实发数量) / `FARJOINQTY`(应收关联数量)。
固化成 `KingdeeUI.grid_all_rows()`。
⚠️ 但**单据详情页**的明细网格 `data('kendoGrid')` 取不到（见「明细网格」），那里的列表页 grid 才走 `kendoKDGrid`。

### 过滤对话框（工具栏「过滤」按钮）
列头漏斗图标是**枚举勾选式**（把 8/25、8/29、9/1… 列出来勾选），**没有「介于」**，不适合区间。

正路：工具栏 → 过滤 → 「列表过滤」对话框。

- 字段 ComboBox：`[id$="_row_Add_PART_Fileds"]`，data item 键 `Caption` / `FieldName`
- 比较符 DropDownList：`[id$="_row_Add_PPART_CompareType"]`，键 `ID` / `Name`
- **值单元格**：⚠️ **先按 id 含 `ppart_value` 定位**（大小写混用，转小写再比）。
  按 `[data-role=...]` 找会**先命中「字段列」的 combobox** → 值写不进去 → 过滤静默失效（界面仍是全部行）。
- 行间逻辑列：`_row_Add_PART_Logic`，value「0」=并且 /「1」=或者。
  ★ 语义是**本行与「下一行」的关系**，所以**最后一行不用设**。
  实测佐证：4 个「或者」条件里末行保持默认「并且」，结果仍是 4 张单全中。
- ⚠️ **末行条件写完值不能立刻点确定**，否则该行条件会被静默丢掉
  （现象：4 张单只筛出 3 张）。见「全局规律 6」下的同名小节。
- 新增行按钮：`LI.kdFilterAdd`
- 取消：`[id$="_Filter-FBTNCANCEL_c"]`（**A 标签**，外层 DIV 不带 `_c`，点 DIV 无反应）
- 确定：`[id$="_Filter-FBTNOK_c"]`（同上，必须精确）

**★ 基础资料字段（客户/部门/业务员）的值控件不是普通 input，塞文本静默无效**
`FCustomerID.FName` 是 **bosf7field 基础资料选择器**，直接写值不生效（实测过滤后仍全部客户）。
要精确筛指定单据 → 用**单据编号** `FBillNo`（Editor.xtype=textfield，可直接写值）
+ **多行「或者」**：
```
FBillNo 包含 XSCKD-105-202608-0121   或
FBillNo 包含 XSCKD-105-202609-0020   或 …
```
比较符共 32 个，没有「介于/区间」：
| 名称 | ID |
|---|---|
| 等于 | 67 |
| 包含 | 17 |
| 大于等于 | 39 |
| 小于等于 | 16 |
| 本月 | 63 |

固化成 `KingdeeUI.set_bill_no_filter(bill_nos)`；改完**必须回读过滤后行数**确认生效。

→ 区间日期要写成**两行**：`<field> >= start` 且 `<field> <= end`

**日期字段区分**（★ 2026-10-29 修正，别再看旧结论）：
- `FDate` = 「日期」= **单据日期** ← **下推出库单筛选用这个**（用户确认口径）

### ★★ 折扣额语义（填 FDISCOUNTAMOUNTFOR 后系统重算，实测）
```
价税合计(FALLAMOUNTFOR_D) = 含税单价 × 数量 − 折扣额
不含税金额(FNOTAXAMOUNTFOR_D) = round(价税合计 / (1 + 税率), 2)
税额(FTAXAMOUNTFOR_D)        = 价税合计 − 不含税金额
```
实测：某行 400×19=7,600，折扣额填 68.28 → 价税合计 **7,531.72**、
不含税 **6,665.24**、税额 **866.48**（13%）。页脚合计同步刷新。

### ⚠️ 「不含税金额」也可编辑，但会连带改「单价」
双击 `FNOTAXAMOUNTFOR_D` 写入值后，系统反算 `FPRICE`(单价) 并**按单价重算金额**，
且**价税合计不变**（只能由 含税单价 / 折扣额 改变）。
实测：24,200 的行把不含税改成 21,223.48，结果 单价→9.5700、不含税→21,054.00、税额→3,146.00，
并非所填数。→ **要精确校正金额，优先考虑调「折扣额」**，或在写入后回读确认。

## 界面八：凭证的提交 / 状态判断（2026-09-21 实测）

### ★ 凭证的「提交」和「审核」是两步（与专票不同！）
| 单据 | 点「提交」后服务端回的 | 是否连带审核 |
|---|---|---|
| 应收单 | **审核成功！保存成功！** | ✅ **保存即审核**（连提交都不需要）|
| 销售增值税专用发票 | **审核成功** | ✅ 提交即审核 |
| 总账凭证（凭证 - 修改页） | **提交成功** | ❌ 审核是独立一步，需再点「审核」 |

⚠️ **别默认套用**：应收单是「保存即审核」，专票是「提交即审核」，凭证是「提交≠审核」——
三类单据三种口径，按上表逐类确认，不要互相类推。

### ★ 判断「这张凭证提交没提交」——看工具栏按钮禁用态（最可靠）
「凭证 - 修改」页工具栏四个按钮的可用性直接映射单据状态：

| 状态 | 保存 | 提交 | 审核 | 还原 |
|---|---|---|---|---|
| 暂存（已生成未提交） | 可用 | **可用** | **灰(disabled)** | 可用 |
| 已提交未审核 | 灰 | 灰 | **可用** | 可用 |
| 已审核 | 灰 | 灰 | 灰 | 可用 |

判据（脚本 `src/submit_voucher.py` 用的）：
- **提交前**：`提交=可用 && 审核=灰` → 确实没提交过
- **提交后**：`提交=灰 && 审核=可用` → 翻转成功 = 提交生效
- `提交=灰` 时直接跳过，避免重复提交

取禁用态的写法（必须过可见性，隐藏页面会污染）：
```js
Array.from(document.querySelectorAll('.kdmenuitem-content'))
  .filter(e => vis(e) && e.offsetParent !== null)
  .forEach(e => { /* e.className 或 e.closest('.kdmenuitem').className 含 'disabled' */ });
```
⚠️ 禁用态是服务端通过 kdsvc 的 **`UpdateMainMenuStates` / `UpdateControlStates`** 下发的，
   点完后要**轮询等 ~1~3s** 才翻过来，点完立刻读会读到旧值。

### ★ 应收单 `-00000N` 子单（别当成"多出来的单据"）

走完"应收单 →下推 专票（分录合并）→ 提交"后，应收单列表里那张单后面会多出 N 张
`父单号-00000N`：**每张 1 行明细、数量/单价/折扣全 0、来源出库单为空、已审核**。

- **是什么**：金蝶「应收单 ↔ 发票」**差异的载体单**，由**发票提交（审核）**时的
  "开票回写"自动产生（创建时间与点提交**同秒**、毫秒级连出）。
- **不是**：不是脚本 bug、不是重复下推、不是垃圾数据。
  （全库 **286 张**同类子单，横跨 2021–2026、数十个客户 ⇒ 系统标准机制）
- **差异两类**：
  1. **分币舍入差** —— 应收单 46 行**逐行**四舍五入不含税；专票「分录合并」成 16 行
     （= 物料种类数）后**按物料汇总**再算 → 顺序不同 → 部分物料各差 1 分、净差 0。
     广源实测：`192稳定剂 +0.01 / TLYZ7绿浆 +0.01 / WF-1052 −0.01 / WF-1062 −0.01`，
     **恰好就是出子单的那 4 个物料**。
  2. **实质金额差** —— 部分开票 / 改价 / 退货（历史子单里的 -504.33、-461538 等）。
- **影响**：子单金额合计 = **0**（广源 6 张 = 0.00/0.00/0.00/−0.01/−0.01/+0.02），
  父单金额不变、**应收余额不重复、账务无影响**，只是列表多几条。
- **排查**：`kq.ar_children(父单号)` → `kq.ar_entries(父单号)` 按物料汇总
  → `kq.iv_entries(专票号)` 按物料汇总 → 比差异。差异在哪个物料，子单就在哪个物料。
- **清场顺序**：子单（反审核→删除）→ 专票 → 凭证 → 父单应收单。**别先删父单**。

## 界面十 · 应收单业务日期（SF-55 现场记录，2026-10-03）

### 单号年月 = 业务日期的年月
`AR105-YYYYMM-####` 里的 `YYYYMM` 取自**业务日期**，与单号规则/创建时间无关。
实测：`AR105-202609-0092..0097` 的 `FDate` 全 = `2026-09-30`（而它们的 `FCreateDate`
都是 `2026-10-03`）。
⇒ **单号月份不对，先回查业务日期**，别去查编号规则。

### 下推后草稿的初始值（实测）
| 字段 | 下推刚出来的值 | 说明 |
|---|---|---|
| `FDATE` | **今天**（2026/10/3） | 必须改 |
| `FENDDATE_H` | **由客户账期 / 结算方式算出**（实测有 2027-01-29） | 不是"今天"，也**不是**业务日期；改 `FDATE` 后金蝶会**重算**（见下） |

### 写 `FDATE` 的三种方式（同一张草稿实测）
| 方式 | 结果 |
|---|---|
| `$(el).data('kendoDatePicker').value(...)` + `trigger('change')` | ✅ **生效**，`FENDDATE_H` 联动 |
| 同上 + 真实鼠标点别处 blur | ✅ 生效 |
| **真实鼠标点击 + `keyboard.type('2026/9/30')`** | ❌ **无效**：掩码框得到 `'20260930'`，widget=None，model 不入 |

⇒ **日期字段只能用 kendoDatePicker API 写，绝不要用键盘打字兜底。**

### ★★ 到期日 `FENDDATE_H` 的联动规则（2026-10-03 二次实测，SF-55 判据修正）

**到期日取什么值由业务规则决定，不是"跟业务日期同一天"。** 实测江西新明峰
（出库单 `XSCKD-105-202609-0196`）：

| 时刻 | `FDATE` | `FENDDATE_H` | 差值 |
|---|---|---|---|
| 下推后、写入前 | 2026-10-03 | **2027-01-29** | 118 天 |
| 写入 `2026-09-30` 后 | 2026-09-30 | **2026-12-29** | 90 天 |

⇒ 两个"想当然"的判据都不成立：
1. **不能**用「到期日 == 业务日期」（有账期的客户永远不满足）；
2. **也不能**用「账期（到期日−业务日期）不变」—— 金蝶**会自己重算**（118 天 → 90 天）。

**正确判据 = 到期日的值「确实变了」**（= 表单 model 收到了 change）：
- 到期日 == 目标值（账期 0 天）→ 通过；
- **写入前业务日期已等于目标值** → 它本来就不该变，放行；
- 否则要求 **到期日 ≠ 写入前基准值**。

仍保住 SF-55 护栏：**widget 骗人（读数变了但 model 没进）⇒ 到期日毫无反应 ⇒ 判失败**。
排查入口：日志里 `[联动基准·写入前] FDATE=... / FENDDATE_H=...` 那一行。
（本次该 bug 让江西新明峰连挂 3 轮、白跑一家；修好后原样重跑一次通过 →
`AR105-202609-0114` / 专票 `SVINV00034068`。）

### 但"写成功"≠"写对了地方"
金蝶 SPA 里**后台标签页的表单 DOM 仍然在**。本批峰值同时存在 **11 个「应收单 - 新增」**。
`[id$="-FDATE-EDITOR_c"]` 用弱可见性 `filter(vis)[0]` 会命中最老那张（孤儿草稿）——
写**真的写进去了**，但**写在了别人身上**，当前单的 FDATE 仍是今天。
⇒ 脚本与日志全程无异常，只有**服务端回读**能发现。修法：
1. `steps.fill_bill_field()` → 用 `_VIS_STRONG.findEditor()`（onTop → 激活面板）**只认前台**；
2. 写完**回读**（`read_foreground_field`），日期型逐日比对，≤3 轮不符则**抛错**；
3. 保存后用 `ExecuteBillQuery` 回读 `FDate`/`FENDDATE_H`（`push_chain.verify_ar_biz_date`）。

### 服务端可用的字段（实测）
| 表单 | 字段 | 含义 |
|---|---|---|
| `AR_receivable` | `FDate` / `FENDDATE_H` | 业务日期 / 到期日（**`FENDDATE_H` 可直接查询**） |
| `SAL_OUTSTOCK` | `FBILLALLAMOUNT` | 出库单**价税合计**（= 应收单明细价税合计 = 目标价税 + 折扣额） |
| `SAL_OUTSTOCK` | `FDate1` | 账务日期；`FDate` = 单据日期。`FALLAMOUNTFOR` **不存在** |
| `SAL_OUTSTOCK` | `FDocumentStatus` | `C` = 已审核（可下推） |

### 重推前必做的两个只读检查
1. **按来源出库单反查应收单必须为空**（`ar_by_source_bill`）—— 否则会推重；
2. **出库单 `FBILLALLAMOUNT` 合计 ≈ 目标价税 + 折扣额**（±0.05）—— 防止拿错单。
