# 广源包装集团「应收单多出来很多」——原因分析

> 分析时间：2026-09-21 19:15~19:25
> 分析方式：**全程只读**（页面查询接口 + 列表数据源），未保存/提交/删除/打开任何单据，未改任何业务数据。
> 结论：**不是脚本出错，也不是重复下推。是金蝶「应收单 ↔ 发票」分币差异的载体单，金额合计 0，账务无影响。**

## 二、根因（铁证）

把「应收单按物料汇总」与「专票按物料」逐项比对：

| 物料 | 应收单不含税 | 专票不含税 | 差异 | 有子单？ |
|---|---|---|---|---|
| 192稳定剂 | 32,414.10 | 32,414.09 | **+0.01** | ✅ 有 |
| TLYZ7绿浆 | 3,665.89 | 3,665.88 | **+0.01** | ✅ 有 |
| WF-1052预印耐磨光油 | 48,235.26 | 48,235.27 | **−0.01** | ✅ 有 |
| WF-1062预印防滑光油 | 59,811.69 | 59,811.70 | **−0.01** | ✅ 有 |
| 163流平剂 / 181消泡剂 / 8950树脂 / 96洋红 / TLA999黑浆 / TLAN5耐晒紫浆 / TLYV102树脂 / TLYV103树脂 / TLYZ1黄浆 / TLYZ3红浆 / TLYZ6蓝浆 / 百威专红 | 一致 | 一致 | **0.00** | ❌ 无 |
| **合计** | **266,824.88** | **266,824.88** | **0.00** | |

**有子单的 4 个物料 ⇔ 有分币差异的 4 个物料，一一对应，无一例外。**

### 为什么会产生这 1 分钱差

```
应收单（46 行）
   每行不含税 = (数量 × 含税单价 − 该行折扣额) ÷ 1.13，逐行四舍五入到分
        ↓ 下推，选「应收单 - 销售专用发票 - 分录合并」
专票（16 行 = 16 种物料）
   每种物料把多行合并成 1 行，按合并后的金额整体算不含税、再四舍五入到分
```

**两次舍入的顺序不同** → 部分物料「逐行舍入之和」≠「汇总后舍入」，各差 1 分。
46 行里恰好有 4 个物料命中，净差为 0（+0.01 +0.01 −0.01 −0.01）。

金蝶在**发票提交（审核）**做「开票回写」时，为这几处差异创建了 `-00000N` 子单来承载。

## 四、排除掉的假设

| 假设 | 结论 | 依据 |
|---|---|---|
| 脚本重复下推，多生成了几张应收单 | ❌ 排除 | 只有 1 张父单（**没有** AR105-202609-0005/0006），金额也正确 |
| 脚本乱建单 | ❌ 排除 | 全库 **286 张**同类 `-00000N` 子单，横跨 **2021–2026**、数十个客户（浙江长海 9 张、卓胜尔 5 张、江门润佳 6 张、PT.Prima 3 张…）⇒ 系统标准机制 |
| 因为加了"行级折扣"引起 | ❌ 排除 | 抽查 3 张历史父单（长海 / 卓胜尔 / 江门润佳），**折扣额全为 0，照样有子单** |
| 金额算错导致 | ❌ 排除 | 父单 266,824.88 / 34,687.22 / 301,512.10 三项全对 |
| 会影响账务 / 重复挂账 | ❌ 排除 | 子单金额合计 0，父单金额未变，应收余额不重复 |

**补充**：历史上的 `-00000N` 子单其实分两类，用的是同一个载体 ——
① **分币舍入差**（如本次广源，±0.01）；
② **实质金额差**（部分开票 / 改价 / 退货，如长海 −504.33、PT.Prima −461,538）。
所以不能一律把子单当垃圾数据。

## 八、怎么才能**不产生**这 6 张子单

> 追加于 2026-09-21 19:40。触发点既然锁定在「发票提交的回写」，就要让**发票逐行金额 == 应收单对应金额**。

### 路径 A（推荐）：下推专票时不选「分录合并」 ★

转换规则下拉里本来就有两项（`steps.py` 的 `RULE_MERGE` / `RULE_NO_MERGE`）：

```
应收单 - 销售专用发票 - 分录合并     ← 用过的（46 行 → 16 行，按物料汇总后再舍入 ⇒ 差 1 分）
应收单 - 销售专用发票 - 分录不合并   ← 46 行 → 46 行，与应收单逐行一一对应 ⇒ 舍入口径完全相同
```

- **原理**：不合并时专票每一行就是应收单的那一行，金额直接继承，没有「汇总后重新舍入」这一步，分币差无从产生 → 子单为 0。
- **代价**：专票行数 = 应收单行数（广源 46 行而非 16 行）。金额、税额、价税合计三项完全一致，不影响账务与凭证。
- **开关**：`python src/push_chain.py ... --no-invoice-merge --yes`
- **残留风险**：我们手工顶平过 seq42（不含税 21,223.47，已偏离 `含税÷1.13` 的口径 2 分）。
  若专票这一行是「按含税重算」而不是「直接继承」，这一行仍可能差 2 分 → 残留 1 张子单。
  **必须实测**：跑完用 `python src/check_subbills.py <应收单号> --detail` 看是不是 0。

### 路径 B（保 16 行合并）：先「按物料掰平」应收单，再下推

把应收单每个物料的**逐行不含税之和**掰到该物料的**汇总后舍入值**（= 专票合并后会得到的值）：
差 δ 时取该物料金额最大的一行做 `不含税 += δ、税额 −= δ`（一增一减 ⇒ 该行价税合计不变 ⇒ 折扣口径不受影响）。

- **算法已就绪**：`discount.plan_material_align(rows)`（纯计算，13+5 项单测全绿）
- **顺序有硬约束**：必须在**下推专票之前、应收单还没审核时**做。应收单已审核时需先反审核
  （此时还没下推，反审核不会被下游挡住）。
- ⚠️ **目标值不能瞎猜**：掰平会让**总不含税移动 `delta_total`**（各物料 δ 之和未必为 0）。
  可靠做法是**闭环**：
  1. 下推专票（合并）→ 读专票 16 行的真实金额（这是"真值"）
  2. **丢弃**这张专票（关标签 → 弹「关闭页签会丢失尚未保存的下推生成数据」→ 点「否」）
  3. 反审核应收单 → 按第 1 步的 16 个真值掰平 → 重新审核
  4. 重新下推专票 → 逐物料与应收单完全一致 → 提交（0 子单）
- **代价**：多一次「下推-丢弃」和一次「反审核-审核」；应收单会有几行出现 1~2 分的「不含税 ≠ 含税÷1.13」。

### 路径 C：接受它（现状）

子单金额合计 0.00、父单金额未变、应收余额不重复 —— **账务上就是没影响**，唯一代价是列表多 6 条要人工识别。
金蝶全库 286 张同类子单横跨 2021–2026、数十客户，说明绝大多数账套就是**这么一直用下来的**。

### 路径 D：改单据转换规则（治本，但属后台配置）

在 BOS 设计器里把「应收单 → 销售专用发票」规则的**金额取数改为直接携带应收单金额，
不按税率重算**，就能从源头消除分币差。RPA 改不了，需要 IT/实施介入。

### ❌ 不建议：下推后手工删子单

子单是**回写差异的载体**，不是垃圾数据。删掉可能让「应收单↔发票」的对应关系断裂；
而账面上它本来就是 0，删了没有任何收益。
