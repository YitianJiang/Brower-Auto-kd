# 应收单 `-00000N` 子单专题

> 现象：走完「应收单 → 下推专票（分录合并）→ 提交」后，应收单列表里那张单后面
> 多出 N 张 `父单号-00000N` 的单，每张 1 行、数量/单价/金额全 0、无来源单、已审核。
> 用户会问"怎么多了这么多应收单"。
> 首次系统分析：广源包装集团，2026-09-21（见项目 `docs/广源应收单子单-原因分析.md`）。

## 一、定性：系统标准机制，不是脚本 bug

它是**金蝶「应收单 ↔ 发票」差异的载体单**，由**发票提交（审核）时的"开票回写"**自动产生
（创建时间与点提交同秒、毫秒级连出）。

**证据**：全库 286 张同类子单，横跨 2021–2026、数十个客户 ⇒ **系统标准机制，不是重复下推**。
⚠️ 不要再把它当成脚本 bug 去"修"。

## 二、差异来源有两大类（同一个载体）

1. **分币舍入差**
   应收单 46 行**逐行**四舍五入不含税；专票按「分录合并」压成 16 行（= 物料种类数）后
   **按物料汇总**再算 → 两次舍入顺序不同 → 部分物料各差 1 分，净差 0。
   > 广源实测：4 个物料 +0.01 / +0.01 / −0.01 / −0.01，
   > **恰好就是出子单的那 4 个物料**。

2. **实质金额差**
   部分开票 / 改价 / 退货（历史子单里的 −504.33、−461538 等）。

## 三、排查套路（全只读，零副作用）

```
kq.ar_children(父单号)      → 拿子单
kq.ar_entries(父单号)       → 拿父单明细，按物料汇总
kq.iv_entries(专票号)       → 拿专票，按物料汇总
→ 比差异
```
**差异落在哪些物料，子单就在哪些物料** —— 这条对应关系是"有子单物料"的判定铁证。

## 四、影响评估

子单金额合计为 0（广源 6 张 = 0.00 / −0.01 / −0.01 / +0.02，合计 0），
**父单金额不变、应收余额不重复、账务无影响**，只是列表"看起来"多了几条。

## 五、清场顺序（还原链路时）

```
6 张子单（反审核 → 删除）→ 专票（反审核 → 删除）→ 父单应收单
                                        ↓
                          凭证：★ 不删，交人工（见下）
```
⚠️ **别先删父单**，子单会挡住。
⚠️ 上面这份顺序是**历史实测记录**（当时连凭证一起删了）；自 2026-09-21 起凭证已被列为红线，
按下面的口径执行 —— **删除顺序到凭证为止，凭证不碰**。

### ★★ 但凭证不在这条链里：**不能删除凭证**

凭证是「单据 → 专票 → 凭证」的终态留痕，金蝶**没有回收站**，删除不可逆；
且删除动作**没有必录校验、不弹错、kdsvc 正常返回**，脚本顺手一点就没了，事后只能回滚数据库备份。
所以即使在做"还原链路"（重跑一单）时：

| 想达到的效果 | ✅ 正确做法 | ❌ 不要 |
|---|---|---|
| 凭证有问题要改 | 「凭证 - 修改」页改摘要/分录后保存 | 删掉重做 |
| 想让这张凭证不进账 | **作废**（保留号码与痕迹） | 删除（不留痕迹） |
| 整单重来 | 先**人工**确认 → 反审核 → 修改重做 | 删凭证再重建 |

代码层面已硬拦截：`Guard.check("delete_voucher")` / `assert_allowed("delete_voucher")`
**永远抛 `GuardError`，与 config 开关、`--yes` 无关**（见 SKILL.md §〇 红线、`scripts/kd_guard.py`）。

> 复核要点：如果你在"还原链路"时发现凭证还挂着，先把单据链拆到"凭证已生成"之前的**新建/草稿**状态，
> 凭证本身交人工处置 —— **不要**让脚本碰它。

## 六、★ 怎么不产生子单（四条路径）

| 路径 | 做法 | 代价 | 可靠度 |
|---|---|---|---|
| **A（首选）** | 下推专票**不选「分录合并」**（转换规则下拉里就有「分录不合并」）→ 专票行数 = 应收单行数，逐行一一对应，没有"汇总后重新舍入"这一步 → 无分币差 | 专票行数变多（46 而非 16） | **高（已实测：子单 0 张）** |
| **B** | 保 16 行合并，但先把**应收单按物料掰平**到"汇总后舍入"口径（差 δ 时取该物料最大行 `不含税+δ / 税额−δ`，价税合计不变） | 需在下推**之前**做、可能要反审核一次；应收单会有几行"不含税≠含税÷1.13" | 高（闭环取专票真值） |
| **C** | 接受它 | 列表多几条 | 100% |
| **D** | 改 BOS 单据转换规则（把金额取数改为**直接携带不重算**） | 需 IT 介入，RPA 改不了 | 治本 |

### 路径 A 的实测结论（2026-09-21）

- 开关：`push_chain.py --no-invoice-merge`
- 广源 2026-09 复跑：专票 `SVINV00033668` 46 行（= 应收单 46 行），
  提交审核后 `kq.ar_children("AR105-202609-0005")` **返回空 ⇒ 子单 0 张**。
- ⇒ **「分录不合并」可避免分币子单**，结论成立。

### 路径 B 注意事项

- 内核：`discount.plan_material_align(rows)`（纯计算，已单测）
- ⚠️ **目标值必须取"专票真实逐物料金额"**（下推一次读出来再丢弃），
  不要用 `round(含税/1.13)` 猜 —— 掰平会让**总不含税移动 `delta_total`**，猜错总账会对不上。

### ❌ 不建议：下推后手工删子单

它是回写差异的载体，删了可能断掉「应收单 ↔ 发票」对应关系，且账面本来就是 0。

## 七、验收工具（幂等、只读）

